# HYROX Training, Accountability and Content Platform

## Project Objective

Extend the existing six-month HYROX workout tracker into a cohesive personal training, health tracking, accountability and content-creation application.

The existing workout plan and weekly tracking functionality should remain intact. The objective is to expand the application rather than replace it.

The finished application should act as a central environment for:

* Following the six-month workout plan
* Recording completed workouts
* Tracking health, recovery and lifestyle information
* Monitoring progress and trends
* Recording notes and reflections
* Creating social-media content from completed activities
* Planning and tracking posts
* Maintaining accountability
* Reviewing weekly and monthly performance
* Building a documented story from beginner to HYROX participant

The application should not feel like several unrelated tools placed together. Workout tracking, health data, progress analysis and content creation should all feed into one another.

---

# 1. Core User Journey

The normal daily process should be:

1. Open the dashboard.
2. See today's planned workout and current priorities.
3. Review sleep, recovery and readiness.
4. Complete the workout.
5. Enter results and notes.
6. Add photos, clips or screenshots where applicable.
7. Record a short post-workout reflection.
8. Allow the app to identify useful progress statistics or story points.
9. Generate or prepare a draft social-media post.
10. Add the post to the content calendar.
11. Mark it as drafted, recorded, edited or published.

The normal weekly process should be:

1. Review planned versus completed workouts.
2. Review sleep, body measurements, running distance and performance.
3. Identify wins, setbacks and lessons.
4. Generate a weekly content summary.
5. Plan the following week's workouts and posts.
6. Record a weekly accountability update.

# 4. Today Page

The Today page should be the main daily working area.

## Morning Check-In

Allow entry of:

* Sleep duration
* Sleep quality from 1 to 10
* Morning body weight
* Body-fat percentage
* Resting heart rate
* Energy from 1 to 10
* Motivation from 1 to 10
* Muscle soreness
* Stress from 1 to 10
* General notes

Use this information to calculate a transparent readiness score.

The app should show how the score was calculated rather than presenting an unexplained result.

* Exercise list
* Sets
* Repetitions
* Distances
* Durations
* Rest periods
* Target pace

* Completed, partially completed, skipped or rescheduled
* Actual duration
* Actual distance
* Average pace
* Average heart rate

* Calories, where available
* Perceived effort from 1 to 10
* Pain or discomfort
* Exercises modified
* Workout notes

* What was difficult

## Quick Content Capture

Immediately after saving a workout, prompt for:

* One-sentence reaction
* Best moment

This should be deliberately quick so that content capture does not become another large task.

# 9. Post Generator

Provide a guided post-generation system.

The user should be able to select a completed workout or milestone and ask the application to assemble a draft.

## Standard short-video structure

Generate content using:

### Hook

A first sentence intended to hold attention.

Examples:

* I nearly skipped this workout.
* Six weeks ago I could not do this.
* This looked much easier on the plan.
* My dashboard said I was improving. The workout disagreed.
* This was supposed to be a recovery session.
* Today I found my weakest HYROX station.

### Context

Briefly explain:

* What the workout was
* Why it mattered
* Where it fits in the programme

### Evidence

Use real recorded information:

* Time
* Distance
* Pace
* Heart rate
* Weight
* Number of rounds
* Previous result
* Personal best
* Consistency streak

### Honest Reaction

Use the saved post-workout reflection.

### Lesson

State one thing learned.

### Next Step

Explain what happens next.

## Suggested output formats

Generate:

* 15-second script
* 30-second script
* 60-second script
* TikTok caption
* YouTube Shorts title
* YouTube Shorts description
* Instagram caption
* Weekly recap outline
* Longer YouTube video outline
* On-screen text
* Shot list
* Thumbnail text ideas

Drafts should always remain editable.

# 17. Accountability System

The accountability system should be supportive rather than punishing.

## Track separate streaks

* Workout streak
* Daily check-in streak
* Weekly review streak
* Content-posting streak

## Missed activity handling

When something is missed:

* Record the reason
* Allow rescheduling
* Avoid resetting all progress messaging
* Prompt for a simple recovery action
* Offer the missed event as a potential honest-content topic

Example:

“Today's workout was missed. Would you like to reschedule it, replace it with recovery work, or record why it did not happen?”

## Accountability prompts

Examples:

* Today's workout has not been logged.
* You completed the workout but have not recorded a reflection.
* A new personal best could make a useful post.
* Your weekly review is due.
* Two drafted posts are ready to record.
* Your sleep has been below your normal level for three days.
* You have completed four consistent weeks.

# 19. Privacy and Safety

The application will contain personal health and lifestyle information.

Include:

* Authentication
* Secure password handling
* Database backups
* Export functionality
* Data deletion
* Private-by-default records
* Clear separation between private data and publishable information
* A preview of exactly what information will be included in a generated post

Never automatically include:

* Home address
* Precise live location
* Private calendar information
* Personal medical information
* Financial information
* Unapproved body measurements
* Hidden metadata from uploaded files

Generated posts should use only information deliberately marked as suitable for sharing.

# 20. User Experience Requirements

The application should:

* Be fast to use after a workout
* Avoid demanding excessive data entry
* Work on a phone
* Use sensible defaults
* Save drafts automatically
* Provide quick-entry buttons
* Allow detailed entry when wanted
* Display clear charts
* Use plain language
* Avoid fitness-industry jargon where possible
* Preserve all existing workout-plan functionality
* Make content creation optional
* Allow sections to be hidden in settings

A normal post-workout log should be completable in approximately two minutes.

# 21. Automation and Future Hermes Agent

Do not make Hermes integration a dependency for the initial application.

Design the application so an agent can be added later.

Potential future agent functions:

* Remind the user about workouts
* Request a morning check-in
* Prompt for a post-workout reflection
* Detect milestones
* Suggest post ideas
* Draft captions
* Prepare weekly recaps
* Identify incomplete content
* Remind the user to record required footage
* Summarise the week's progress
* Identify changes in training performance
* Ask why a workout was missed
* Suggest the next best accountability action

The application should expose appropriate internal functions or API endpoints so a future agent can:

* Read today's workout
* Read recent health entries
* Save reminders
* Create content ideas
* Create draft posts
* Read weekly results
* Mark tasks as completed

No agent should publish content or change the training plan without explicit approval.

# 22. Development Approach

Before modifying the application:

1. Inspect the existing project structure.
2. Identify the framework, database and current components.
3. Document the existing workout-tracking functionality.
4. Reuse current styles, components and data models.
5. Identify any existing features that overlap this brief.
6. Create a phased implementation plan.
7. Preserve existing data.
8. Add database migrations rather than recreating the database.
9. Implement and test one phase at a time.
10. Update documentation as work progresses.

Do not rewrite the entire application unless there is a clear technical reason.
